# S3 Sink

varTrack writes config values to S3 as objects. S3 is ideal for audit storage, batch pipelines, and config files read by many services.

---

## Configuration

```cue
datasources: [{
  s3: {
    tag:               ""
    bucket:            "my-config-bucket"
    region:            "us-east-1"
    access_key_id:      "AKIA..."
    secret_access_key:  "..."
    endpoint:          ""    // optional — set for MinIO or other S3-compatible stores
  }
}]
```

### MinIO / S3-compatible

```cue
datasources: [{
  s3: {
    bucket:            "configs"
    endpoint:          "http://minio:9000"
    access_key_id:      "minioadmin"
    secret_access_key:  "minioadmin"
    region:            "us-east-1"
  }
}]
```

### IAM role (no credentials)

For services running on AWS with an instance role or IRSA:

```cue
datasources: [{
  s3: {
    bucket:       "my-config-bucket"
    region:       "us-east-1"
    use_iam_role: true   // no access_key_id / secret_access_key needed
  }
}]
```

## Destination template

The `destination_template` sets the S3 key prefix:

```cue
rules: [{
  platform:             "github"
  datasource:           "s3"
  destination_template: "{tenant}/{env}/"
}]
```

## Write strategies

The datasource's `update_strategy` decides what is written under the prefix:

```cue
datasources: [{
  s3: {
    bucket:          "my-config-bucket"
    update_strategy: "STRATEGY_DOCUMENT"   // or "STRATEGY_KEY_VALUE", "STRATEGY_FILE"
  }
}]
```

| `update_strategy` | Objects under the prefix |
|---|---|
| `STRATEGY_KEY_VALUE` | One object per key: `acme/production/database.host` holds `mongo.prod.internal` |
| `STRATEGY_DOCUMENT` | `config.json`, always nested: `{"database": {"host": "mongo.prod.internal"}, "max_connections": 50}` |
| `STRATEGY_FILE` | `config.json`, in the shape the file parsed to: nested for YAML, JSON, TOML…, flat for `.env` and `.properties` |
| unset | One object per key with `one_file_per_key: true`; otherwise `config.json` with the keys flat: `{"database.host": "mongo.prod.internal", "max_connections": "50"}` |

`STRATEGY_DOCUMENT` and `STRATEGY_FILE` keep the types and arrays the file has. A flat file under `STRATEGY_DOCUMENT` is nested by the dots in its keys; one where a key is both a value and the parent of other keys fails to sync. Use `STRATEGY_FILE` for that file.

## Server-side encryption

```cue
datasources: [{
  s3: {
    bucket:               "my-config-bucket"
    sse_algorithm:        "AES256"     // or "aws:kms"
    // sse_kms_key_id:    "arn:aws:kms:..."  // only for aws:kms
  }
}]
```

| Algorithm | Description |
|---|---|
| `AES256` | S3-managed keys (SSE-S3) |
| `aws:kms` | AWS KMS key (SSE-KMS) — specify `sse_kms_key_id` |

## Object versioning

```cue
datasources: [{
  s3: {
    bucket:            "my-config-bucket"
    enable_versioning: true   // enable S3 bucket versioning
  }
}]
```

When enabled, each write creates a new object version, preserving full config history.

---

## Drift detection

The watcher lists all objects under the configured prefix and compares their ETags against the baseline. Objects are only re-downloaded on ETag mismatch, keeping bandwidth low.

```cue
rules: [{
  platform:   "github"
  datasource: "s3"
  self_heal:  true
}]
```
